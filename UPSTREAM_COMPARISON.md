# Phase 0: upstream reference and regression checks

This fork starts from TUM-VT/FleetPy commit
`c813728b6d188df8dd7fd5d3d36dcb0a55c898a2`. Phase 0 adds a regression safety
net and fixes four categories of upstream defect. It does not add driver
acceptance, ETA noise, AV rules, or new matching/repositioning policies.

## Reference provenance

The approved CSV files in `tests/regression/baselines/` were generated from a
clean `git archive` of that upstream commit **before applying the fixes**.
They were not generated by accepting the changed fork's output. The same
runner executes the upstream archive and the fork, in separate Python
processes, with one optimization thread and `PYTHONHASHSEED=0`.

The runner redirects only the result directory and disables console progress;
the original bundled scenario, demand, routing, and dispatch logic execute.
Results go to fresh temporary directories, so existing study results are not
erased. No separate Git checkout or worktree is needed.

`tests/regression/baselines/manifest.json` records the upstream SHA, Python and
package versions, runtime overrides, and SHA-256 hashes of the input files.
The capture used Python 3.10.22, NumPy 2.2.6, pandas 2.2.3, SciPy 1.15.3,
PyYAML 6.0.2, and Gurobi 12.0.1.

| Example | Operator | Requests | Picked up |
| --- | --- | ---: | ---: |
| insertion | PoolingIRSOnly | 100 | 93 |
| immediate_batch | PoolingIRSAssignmentBatchOptimization | 100 | 93 |
| batch | RidePoolingBatchAssignmentFleetcontrol / AlonsoMora | 100 | 93 |

Each regression test runs the complete two-hour bundled scenario and compares
all 48 evaluation rows and every column of all 100 rider output rows, with
exact numeric equality and matching missing values. Rider rows are sorted by
request ID; duplicate or missing riders fail the check. A subprocess error,
timeout, or missing final state also fails the test.

This establishes exact equality of these recorded outputs for these three
examples and the recorded runtime. It does **not** establish byte-for-byte
identity of the entire simulator, arbitrary scenarios, solver debug files,
logs, wall-clock timings, or other toolchain versions. The fixed fault paths
intentionally differ from upstream's crashing or incorrect behavior.

## Fixes and targeted coverage

1. Batch retry called the removed `delRequest` method. It now calls the
   optimizer's existing `delete_request` interface, extends the pickup window,
   and registers the request again.
2. The second-attempt rejection branch used `prq` from an earlier loop. It
   could raise `UnboundLocalError` or reject the wrong request. It now looks up
   the request for the current ID. Tests cover both an empty first loop and a
   first loop containing another request.
3. Aggregated forecasts called nonexistent pandas `groubpy`. Zone aggregation
   now uses `groupby` and an explicit `sum` aggregation. Arrival and departure
   totals are checked against hand-computed counts.
4. Sampling-based repositioning had debug solution/problem dumps enabled by
   default. The ordinary and reservation variants now default to no dumps.
   The diagnostic code remains available behind the existing module flags.

Before the fixes, all five targeted unit cases failed. After the fixes, they
pass alongside the three full-simulation regression cases. The disabled dump
defaults were inspected directly; the large sampling/repositioning optimizer
is not exercised by these three baseline scenarios.

## Run the checks

From the repository root, after installing the runtime dependencies:

```bash
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

The full suite requires Gurobi; the bundled examples fit its restricted
small-model license. Unit checks without optimization are available with:

```bash
python -m pytest -q -m "not integration"
```

The Phase 0 subset contains eight cases: five focused unit cases and three
complete simulations. The full suite now also includes Phase 1; see
`docs/PHASE_1.md`. Optimizer cases are not silently skipped if Gurobi is
missing or unusable.

## Reproduce, do not silently bless, reference results

Capture a new independent copy from the recorded Git revision:

```bash
python tools/capture_example_baselines.py --output /tmp/fleetpy-reference-review
diff -r tests/regression/baselines /tmp/fleetpy-reference-review
```

The destination must not already exist. The capture tool never overwrites
approved fixtures, runs working-tree application code as the reference, or
regenerates baselines during tests. Any intentional baseline update requires
reviewing the source revision, dependency versions, input hashes, and changed
metrics. `--revision` supports explicitly reviewing a later upstream revision;
the regression test's pinned revision must be reviewed with such an update.

## Known follow-up outside Phase 0

`src/preprocessing/demand/aggregate_trip_demand.py` still contains
`demand_df = demand_df.notna()`, which replaces the data with a boolean mask.
The bundled baseline scenarios read existing demand files and do not use that
generator. Fixing and validating custom-demand preprocessing is a separate
task; Phase 0 does not claim that pipeline is ready.


## Phase 11: broader native fidelity validation

The Phase0 reference provenance and approved baseline files above remain
unchanged. The [Phase11 gate](docs/PHASE_11.md) now compares clean upstream
and the current fork on all four physical output tables, with import isolation,
actual booking completion and exact fresh-process repeatability. Complete native
Munich, Chicago and Manhattan profiles and a clean published-source archive
also match byte for byte in the declared matched profiles. The declared router,
repositioning and timeout adaptations limit this claim; it is not universal
identity of all simulator internals, configurations or known upstream faults.
Read the [measured results](docs/validation/phase11/RESULTS.md) and
[full source/input/output evidence](docs/validation/phase11/README.md).
